The budget brain that replaces CBO / Advantage+ allocation

The optimizer takes a portfolio of Meta ad sets with raw 3/7/14-day metric windows and reallocates a fixed daily budget toward the best performers — conserving the total exactly (Σ proposed = total), enforcing per-ad-set guardrails, and emitting pause recommendations that always require human approval.

It is a pure-TypeScript engine (@continuum/optimization-engine, Zod only at the IO edge) wrapped by a Next.js UI. Behaviour is data-calibrated per objective (18 months of Meta data: 26 accounts, $37.4M spend, 440k ad-day rows) and additive: with no objective set it reproduces the original Excel model 1:1.

Objective profiles — the calibrated knobs

objectives.ts · OBJECTIVE_PROFILES

Asymmetric caps

Cuts never penalise CPA; raises are safe to ~50%. So down-caps are wider — except saturating objectives (purchase, lead) keep raises tight.

Lead is special

Noisiest objective (Spearman ≈0.45). 3d is noise → de-weighted; it gets the significance gate + EWMA smoothing + cautious caps.

Weights are robust

Re-weighting barely moves predictiveness (+0.00–0.03 Spearman). The numbers are principled, not over-fit.

The engine pipeline

runCycle() orchestrates all five stages
A · Pacing pacing.ts → computePacing()
in periodBudget · periodDays · dayIndex · actualSpendToDate
out dailyTotal (linear catch-up) · status: on_track / under / over

Decides how much to spend today from the period plan vs actual spend. Feeds the budget total into reallocation.

▼dailyTotal
B · Classify classify.ts → classifyPortfolio()
in snapshots + resolved config
out per-ad-set status
  • frozen manual freeze, or age < 3d (budget fully locked)
  • grace age < newItemProtectDays (7) → gets average active score
  • learning objective-KPI events in 7d < threshold, or age < 7d
  • active everything else
▼classified snapshots
C · Triggers triggers.ts → evaluateTriggers()
in classified snapshots
out Recommendation[] (needsApproval) + starve set
  • P1 zero upper funnel — fast, 3d
  • P2 sustained poor vs a robust P25 cost reference — 14d
  • P3 dead weight (spent enough, ~zero results) — 14d

⚠ never auto-pauses

Triggers only emit recommendations (all needsApproval: true) and mark the ad set starved so the solver drives it toward its floor in the meantime. KPI counting is objective-aware.
▼starved marks + pool
D · Reallocate engine.ts · scoring.ts · solver.ts
in snapshots · total · resolved config · priorComposites
out ReallocationResult (per-item budgets + diagnostics)

D1 · Score scoreAdSet()

  • window score = events / spend on the objective KPI
  • trajectory 3d vs 7d → pick positive / neutral / negative weight set
  • significance gate drops sub-threshold windows; composite renormalised
  • saturation γ, then EWMA blend with prior composite

D2 · Solve solve() · water-filling

  • pool = total − frozen; floor = max(% of avg, target·minSignals/window)
  • box per item: lo = max(floor, cur·(1−down)), hi = max(cur·(1+up), floor)
  • learning keeps the −8% down-cap as an additional floor
  • iteratively assign ∝ score, clamp to box, re-fill → Σ = total exactly

Precedence on conflict

Conservation > Floor > Velocity cap. Overflow modes: breach_best (default) · underspend · relax_uniform.
▼budgets shaped by mode
E · Mode runCycle.ts
in reallocation + mode
out CycleResult { pacing, reallocation, recommendations }

balanced

Spend the planned total exactly (overflow → breach best).

efficiency

Total is a ceiling — underspend rather than fund bad inventory.

scale

Grow up to maxBudget while portfolio cost-per-KPI ≤ target.

Config resolution & precedence

config.ts → resolveConfig()

Layered merge (lowest → highest)

DEFAULT_CONFIG — Excel model 1:1 (the additive baseline)
applyObjectiveProfile() — overlays the calibrated profile
portfolio overrides — saved settings (target, caps…)
review overrides — this-reallocation-only tweaks

Higher layers win. Each layer only sets the keys it cares about; the rest fall through.

Why additive matters

With no objective, kpiField is unset and the engine takes the legacy purchase path (Tier-1 1/CPP, Tier-2 ATC proxy, symmetric ±cap). That reproduces the original Excel sheet exactly —

✓ fidelity preserved

The Excel-fidelity tests never pass an objective, so they stay green. Objective handling is purely opt-in.

When an objective is set, scoring switches to events/spend on its KPI and caps become asymmetric.

7

Cross-cutting invariants

verified by the test suite

① Conservation Σ = total

Final budgets always sum to the day's total (water-filling + reconciliation). Top guardrail — it never yields.

② No auto-pause

The system only lowers budget to a floor (starved) and recommends. A human approves every pause.

③ Additive

No objective ⇒ exact Excel behaviour. Turning a profile on never breaks conservation.

④ Pure & bounded

Dependency-free TypeScript (Zod only at the edge). No network, no DB inside the engine — trivially testable & portable.
